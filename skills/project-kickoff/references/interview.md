# Interview Guide

Use only the sections needed to resolve meaningful uncertainty. Do not ask questions already answered in the conversation or project files.

## Core prompts
- What problem are you solving, for whom, and what outcome would make this project worthwhile?
- What is the smallest useful first version? What is explicitly out of scope?
- What are the main user journeys or inputs and outputs?
- Are there technical, platform, accessibility, privacy, budget, or deadline constraints?
- Is a stack or architecture already chosen? If not, would you like a recommendation?
- What does “done” look like for each major milestone, and how could it be checked?
- What risks or dependencies could change the plan?
- Which choices are already settled, and which should remain open for the implementation phase?

## When the user is unsure
Offer one practical default with a brief reason and ask whether to adopt it, leave it open, or choose another option. Mark an unconfirmed suggestion as a proposal, never as a decision.

## Existing plans or skipped interviews
Treat user-provided plans as source material. Summarize them, check for contradictions and missing approval-critical details, and ask only targeted questions. If the user asks to skip discovery, proceed with explicit assumptions and open questions instead of blocking the workflow.

## Stop condition
Stop when each plan section can be populated using confirmed facts, labeled proposals, or explicit unknowns, and the user has had a chance to correct the summary. Do not pursue completeness for its own sake.
